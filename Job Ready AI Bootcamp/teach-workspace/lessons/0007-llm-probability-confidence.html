LLM-এর Probability ও Confidence

বাংলায়: “LLM আসলে লেখে না — প্রতিটা শব্দে একটা probability distribution বানায়, তারপর সেখান থেকে তোলে।”

১. LLM মানেই একটা probability মেশিন

ChatGPT বাক্য “লেখে” না। ও প্রতিবার শুধু একটা প্রশ্নের উত্তর দেয়:

P( পরের token | এ পর্যন্ত যা আছে )

“আকাশের রং ___” দিলে মডেল পুরো vocabulary-র (~১,০০,০০০ token) উপর একটা distribution বানায়:

নীল    0.72
কালো   0.09
ধূসর   0.06
লাল    0.002
...  (বাকি ৯৯,৯৯৬ টা token)
মোট যোগফল = 1.00

তারপর সেখান থেকে একটা তোলে, বাক্যে জোড়ে, আবার একই প্রশ্ন করে। পুরো বাক্যের probability হলো গুণফল:

P(বাক্য) = P(w₁) × P(w₂|w₁) × P(w₃|w₁,w₂) × …

এটাই chain rule of probability — পাঠ ৪ এর conditional probability P(A|B) এর সরাসরি প্রয়োগ। LLM মানে বিশাল আকারের একটা conditional probability টেবিল, যেটা মুখস্থ না করে শিখে ফেলা হয়েছে।

২. Logits → Softmax → Probability

মডেলের শেষ layer থেকে যা বের হয় তার নাম logits — যেকোনো সংখ্যা, ঋণাত্মকও হতে পারে। Probability বানাতে softmax লাগে:

pi = exp(zi / T) / Σ exp(zj / T)
import numpy as np

def softmax(logits, T=1.0):
    z = np.array(logits) / T
    e = np.exp(z - z.max())        # স্থিতিশীলতার জন্য max বাদ
    return e / e.sum()

logits = [3.2, 1.1, 0.8, -0.5]
softmax(logits, T=1.0)   # [0.81, 0.10, 0.07, 0.02]  ← ধারালো
softmax(logits, T=2.0)   # [0.55, 0.19, 0.17, 0.09]  ← নরম
softmax(logits, T=0.3)   # [0.99, 0.00, 0.00, 0.00]  ← প্রায় নিশ্চিত

Temperature — যে নবটা তুমি API-তে দাও

Tযা হয়কখন
০ এর কাছেসবসময় সবচেয়ে সম্ভাব্য token — একঘেয়ে, পুনরাবৃত্তিকোড, তথ্য, JSON
~০.৭ভারসাম্যসাধারণ চ্যাট
১.৫+distribution চ্যাপ্টা, বিরল token-ও আসে — সৃজনশীল, কিন্তু আবোলতাবোলগল্প, brainstorm
সংযোগ Temperature আসলে distribution-এর ছড়ানো নিয়ন্ত্রণের নব — ঠিক পাঠ ১ এর σ যা করত। T বাড়ানো মানে ঘণ্টা চ্যাপ্টা করা।

Top-k আর Top-p (nucleus)

Temperature বাড়ালে একটা বিপদ — অত্যন্ত অসম্ভাব্য token-ও (probability ০.০০০১) কখনো কখনো উঠে আসে, আর একটা বাজে শব্দ পুরো বাক্য নষ্ট করে। তাই লেজটা কেটে দেওয়া হয়:

  • Top-k = 50 → শুধু সবচেয়ে সম্ভাব্য ৫০টা token থেকে তোলো।
  • Top-p = 0.9 → উপর থেকে যোগ করতে করতে ৯০% probability যেখানে পূর্ণ হয়, সেখানেই থামো। বাকিটা বাদ।

Top-p বেশি চতুর: মডেল নিশ্চিত হলে হয়তো ৩টা token-ই ৯০% পূরণ করে; অনিশ্চিত হলে ২০০টা লাগে। মানে কাটার জায়গাটা নিজে থেকেই মানিয়ে নেয়।

৩. Confidence মাপা — পাঠ ৫ এর সরাসরি প্রয়োগ

(ক) Token-level: logprob

অনেক API প্রতিটা token-এর logprob (log probability) ফেরত দেয়। exp(logprob) করলেই confidence:

token "নীল"  logprob = -0.33  → exp(-0.33) = 0.72  ← আত্মবিশ্বাসী
token "১৯৪৭" logprob = -2.30  → exp(-2.30) = 0.10  ← দুর্বল, যাচাই করো

ব্যবহারিক নিয়ম: extraction বা classification-এ যদি উত্তরের token-গুলোর logprob কম হয়, তাহলে মানুষের কাছে পাঠাও। এটাই পাঠ ৫ এর threshold সিস্টেম, LLM-এ বসানো।

(খ) Sequence-level: Perplexity

Perplexity = exp( − (1/N) Σ log p(wi) )

মানে: “প্রতি শব্দে মডেল গড়ে কয়টা বিকল্পের মধ্যে দ্বিধায় ছিল?” PPL = ১ মানে নিখুঁত নিশ্চয়তা। PPL = ১০০ মানে প্রতি শব্দে যেন ১০০টা সমান বিকল্পের মধ্যে আন্দাজ করছে।

(গ) মডেলকে সরাসরি জিজ্ঞেস করা

Anthropic-এর গবেষণায় দেখা গেছে বড় মডেল নিজের উত্তর সঠিক কিনা তা নিয়ে মোটামুটি সৎ P(True) দিতে পারে — অর্থাৎ মডেল কিছুটা “জানে যে সে জানে না”। নিখুঁত নয়, কিন্তু ফেলনাও নয়।

(ঘ) Semantic Entropy — hallucination ধরার সেরা উপায়

সমস্যা: “১৯৭১”, “উনিশশো একাত্তর”, “1971 সালে” — তিনটা আলাদা token সিকোয়েন্স, কিন্তু একই অর্থ। শুধু token probability দেখলে মনে হবে মডেল দ্বিধায়, আসলে না।

সমাধান:

  1. একই প্রশ্ন ৫–১০ বার চালাও (temperature > 0)
  2. উত্তরগুলো অর্থ অনুযায়ী দলে ভাগ করো (একটা NLI মডেল দিয়ে)
  3. দলগুলোর উপর entropy মাপো
সব উত্তর একই দলে      → entropy কম  → মডেল সত্যিই জানে
উত্তর ৫টা আলাদা দলে   → entropy বেশি → সম্ভবত hallucination
এটা কেন Frequentist পাঠ ৩ এর হুবহু কৌশল — “একবার দেখে বোঝা যাচ্ছে না? তাহলে বহুবার চালিয়ে গুনে দেখো।” LLM-এর অনিশ্চয়তা মাপার সবচেয়ে নির্ভরযোগ্য পদ্ধতিটা আসলে law of large numbers।

৪. Calibration — LLM-এর সবচেয়ে বড় ফাঁদ

পাঠ ৫ এ বলেছিলাম confidence ≠ accuracy। LLM-এ এটা ভয়াবহ রকম সত্যি:

ধাপCalibration
Pre-trained base modelবেশ ভালো — ০.৮ বললে সত্যিই ~৮০% বার ঠিক
RLHF করার পরখারাপ হয়ে যায় — সব কিছুতেই অতি-আত্মবিশ্বাসী

GPT-4 এর technical report-এ এই পতনটা গ্রাফসহ দেখানো আছে। কারণটা বোধগম্য: RLHF মডেলকে শেখায় মানুষ যে উত্তর পছন্দ করে সেটা দিতে, আর মানুষ দ্বিধাগ্রস্ত উত্তর অপছন্দ করে। ফলে মডেল আত্মবিশ্বাসী ভঙ্গিতে বলা শিখে যায় — জানুক বা না জানুক।

ইঞ্জিনিয়ার হিসেবে যা করতে হবে LLM-এর “আমি নিশ্চিত” কথাটাকে কখনও confidence score হিসেবে ধরবে না। মাপো — logprob, বা একাধিকবার চালিয়ে semantic entropy। তারপর নিজের validation set-এ calibration curve এঁকে দেখো দাবি আর বাস্তব মেলে কিনা।

মজার মিল: calibration ঠিক করার ক্লাসিক পদ্ধতির নামও temperature scaling — একই softmax temperature, কিন্তু এবার validation set-এ fit করে বসানো হয় (Guo et al. 2017)।

৫. Frequentist দিক — benchmark-এর সংখ্যা কতটা বিশ্বাস করবে

“আমাদের মডেল MMLU-তে ৮৭.২%, ওদেরটা ৮৬.৯%” — এটা কি সত্যিই ভালো?

পাঠ ৩ এর SE বের করো। n = ১৪,০০০ প্রশ্ন, p ≈ ০.৮৭:

SE = √(0.87 × 0.13 / 14000) = 0.0028
95% CI = 87.2% ± 0.56%  →  [86.6%, 87.8%]

৮৬.৯% ওই রেঞ্জের ভেতরেই পড়ে। মানে পার্থক্যটা noise। আর ২০০ প্রশ্নের কোনো ছোট eval set হলে CI হবে ±৫% — সেখানে ১-২% পার্থক্য নিয়ে কথা বলাই অর্থহীন।

নিজে পরীক্ষা দাও

Temperature ২.০ করলে softmax distribution-এর কী হয়?

T ভাগ হিসেবে বসে — বড় T মানে logits ছোট হয়ে যায়, পার্থক্য কমে, distribution সমান হয়ে আসে। পাঠ ১ এর σ বাড়ানোর সমতুল্য।

RLHF-এর পর মডেলের calibration সাধারণত কী হয়?

RLHF মানুষের পছন্দ শেখায়, আর মানুষ দ্বিধা অপছন্দ করে। GPT-4 report-এ pre/post-RLHF calibration গ্রাফে পতনটা স্পষ্ট।

Semantic entropy-তে উত্তরগুলো কীসের ভিত্তিতে দলে ভাগ করা হয়?

এটাই মূল কৌশল। "১৯৭১" আর "উনিশশো একাত্তর" token হিসেবে আলাদা, অর্থে এক — একই দলে যাবে। তাই entropy কম, অর্থাৎ মডেল আসলে নিশ্চিত।

মনে করে লেখো: কোনো LLM-এর একটা উত্তরে সে কতটা নিশ্চিত — তুমি কীভাবে মাপবে? দুইটা আলাদা উপায় লেখো।

মিলিয়ে দেখো (১) Logprob — উত্তরের token-গুলোর log probability নাও, exp() করো, threshold বসাও। এক কলেই হয়, কিন্তু শব্দরূপে বিভ্রান্ত হয়। (২) Semantic entropy — একই প্রশ্ন ৫–১০ বার চালাও, উত্তরগুলো অর্থ অনুযায়ী দলে ভাগ করো, entropy মাপো। বেশি খরচ, কিন্তু hallucination ধরায় অনেক ভালো। আর যাই করো — মডেলের নিজের "আমি নিশ্চিত" বাক্যটা confidence হিসেবে গুনবে না।
